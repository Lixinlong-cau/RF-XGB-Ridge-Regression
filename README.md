# RF + XGBoost + Ridge stacking analysis

This directory contains a reproducible implementation of the stacking models described in the manuscript. The rewritten `code.py` replaces the original script, which is retained as `code_legacy.py`.

## Main revisions

1. Categorical predictors use one-hot encoding rather than `LabelEncoder`.
2. Numeric and categorical imputation, scaling, and encoding are fitted inside each training partition only.
3. Hyperparameter tuning is nested inside each outer training partition.
4. Validation supports:
   - the supplied 80/20 holdout;
   - record-level five-fold cross-validation;
   - five-fold cross-validation with complete site-year experiments held within folds.
5. RF and XGBoost out-of-fold predictions are used to construct the stacking meta-features.
6. Ridge regularization is selected only from training-partition out-of-fold predictions.
7. Permutation importance is calculated for the original raw predictors rather than individual one-hot dummy columns.
8. Model metrics, predictions, metadata, fitted models, and figures are written under `results/`.

The script does **not** generate numerical results for the constrained water-nitrogen scenario. It is limited to model fitting and validation.

- prediction-comparison and importance figures

## Definitions used by the code

- Site-year group: `sowing year + latitude + longitude`
- Primary grouped validation: complete site-year groups remain within one fold
- Record-level validation: individual records are shuffled across folds
- Ridge input: out-of-fold RF and XGBoost predictions
- Numeric missing values: training-partition median
- Categorical missing values: training-partition most-frequent value
- Unknown categories in held-out data: ignored by the one-hot encoder

## Important note on reported metrics

The revised preprocessing and nested validation are intentionally different from `code_legacy.py`. Consequently, rerun validation metrics may differ from the values produced by the old script. Use the outputs from this script when updating the manuscript and supplementary tables, and do not mix metrics generated by the legacy and revised pipelines.

The corrected WUE unit conversion is:

```text
WUE (kg/m3) = Yield (kg/ha) / [10 x ET (mm)]
```
